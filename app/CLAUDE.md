# CLAUDE.md — `app/` (native)

Loaded when working under `app/`. Station-wide architecture lives in the root `CLAUDE.md`.

### Native app (`app/`)

A separate **Expo SDK 57 / React Native** project (own `package.json`, `node_modules`, `eas.json`) — the native iOS + Android player. It ports the web player's hooks/UI to RN + NativeWind, with the same listener experience (now-playing, booth, timeline, requests, schedule, themes, a Skia visualiser). Background audio + lock-screen / CarPlay / Android Auto controls come from **`react-native-track-player`** (wrapped in `src/audio/player.ts` so it's swappable). Like the web player, it's a player for *any* station: the base URL is fully runtime (`StationContext` → `createApi(baseUrl)`), defaulting to the public station, and listeners can add stations by address. Saved station URLs are always credential-free; optional HTTP Basic Auth credentials live in Expo SecureStore and are attached only as station-scoped headers by the live API client, including the explicit stream header AVPlayer requires. Stream defaults to the MP3 floor (`/stream.mp3`); listeners can pick the optional Opus/FLAC/AAC mounts per station via the back panel's SIGNAL row (`lib/streamFormat.ts` gates the choice on the `/now-playing` `stream` flags AND platform decodability — iOS AVPlayer can't demux Ogg, so Opus/FLAC are Android-only; Cast stays MP3). `service.ts` wires remote Play/Pause/Stop but **not skip** (shared live stream).

Architecture-critical and easy to break — read [`app/docs/TESTING.md`](app/docs/TESTING.md) before touching native config:

- **New Architecture is mandatory** (RN 0.86 ignores `newArchEnabled=false`). Reanimated 4 requires it. RNTP 4.1.2 isn't natively new-arch-compatible, so `app/patches/react-native-track-player+4.1.2.patch` carries the fix; without it Android crashes on the first playback event. The patch also fixes live media-session progress (#857). When changing the patch or upgrading RNTP/KotlinAudio, read the adapter and device-check rules in [`app/docs/TESTING.md`](docs/TESTING.md).
- **The Live Activity is native, so OTA can't reach it.** The on-air card (Lock
  Screen, Dynamic Island, and — the point — the **Apple Watch Smart Stack**, which
  iOS 18+ mirrors it into for free) is a widget extension in `targets/live-activity/`
  plus a local Expo module in `modules/live-activity/`, driven by
  `src/hooks/useLiveActivity.ts`. React Native does not run on watchOS, so this is
  the wrist without a second codebase (a real watch app is #1488). Its SwiftUI ships in the binary: an
  `expo-updates` OTA changes the hook, never the card. `SubwaveLiveAttributes.swift`
  is compiled into both targets and `npm test` fails if the copies drift — a
  mismatch silently stops the card rendering rather than failing the build. Full
  rules in [`app/docs/TESTING.md`](docs/TESTING.md).
- **`ios/` and `android/` are gitignored** (Continuous Native Generation) — regenerated from `app.json` + `assets/` by `expo prebuild` / EAS. The source of truth for icons/splash is `assets/` (disc-mark branding) + `app.json`.
- **A private station has its own password, apart from the Station login** (#478). `/state`'s `privacy` flags drive `useStationGate`: the private player hides the whole face until the password is in (`checking` counts as hidden), stream-only auth prompts over it. Every check is the fail-CLOSED `POST /station-auth`, never `/listener-auth`. The password lives in `lib/station-password.ts`'s own secure-storage key and rides the stream as `?auth=` (so Cast works), while a proxy login keeps its `Authorization` header — Icecast admits on either. `createApi` reads the password through a getter at stream-URL time, so unlocking never changes the client's identity: several hooks (the feed reset, the Live Activity lifecycle) key on it.
- **No payment call-to-action in the app.** The back panel's About sheet links to the project site, the setup guide, the source and Discord (`src/lib/links.ts`). The Ko-fi link lives on the site footer instead. A donate or tip link to the developer inside the binary fails App Store 3.1.1 and Play's Payments policy outside the US, and the app is live on both stores.

Distribution is **EAS cloud builds** → iOS TestFlight + Android internal-distribution link (project `@pinku1/subwave`, bundle `com.getsubwave.app`). The repeat-release workflow lives in the `subwave-app-ios-release` and `subwave-app-android-release` skills; getting it onto a physical Android phone over USB is `subwave-app-android`. See `app/README.md`.

### Fork contracts

- The MP3/AAC/Opus/FLAC preference is stored per station base URL. The effective format must also be advertised by that station and decodable by the current platform; otherwise playback falls back to MP3. Never reuse one station's preference for another.
- Listener-time fallback uses the active format's `stream.bufferSecondsByFormat` value and only then the legacy `stream.bufferSeconds`. Keep `activeStreamFormatRef` wired through `PlayerScreen` to `useStationFeed`; native has no measured browser-buffer lag.

- Native feed polling is serialized and cancellable. The API deadline must cover JSON body consumption, not just response headers; otherwise a stalled body can permanently block later polls. Keep outer cancellation wired until the body settles. `scripts/api-timeout.test.ts` covers retry and station-change cancellation.

### v1.29 playback and login contracts

- **The station password is not the station login** (#478). Every check is the fail-closed `POST /station-auth`, and only the controller's own answers count: a 200 with its `{ ok: true }` body is a right password and a 401 with its `{ ok: false }` body a wrong one, while anything else keeps a saved password and saves no typed one (`stationAuthResult`, #2143, #2164); the password rides the stream as `?auth=` so Cast works; `createApi` reads it through a getter because the feed reset and the Live Activity lifecycle key on the `api` object's identity, so rebuilding the client on unlock would reset both. While playback is stuck, `src/lib/stuck-password-check.ts` asks again after every answer but a denial, never within 120 s of the last check or before a 429's `Retry-After` runs out, capped at the route's own window: it allows a household's address 20 attempts per 15 minutes (#2141, #2164).
- **Every stream reload goes through `src/lib/stream-recovery.ts` while the player is mounted** (#2114, #2139): one at a time, and never on a state event alone. A listener's own load (a tune-in, a retune, a Play from the lock screen, a headset, CarPlay or Bluetooth) always loads, queued behind one in flight. `service.ts` hands a remote Play to the mounted player (`src/lib/remote-play.ts`) and loads directly only when none is mounted, which Android's headless service allows. The watchdog, churn guard and error backoff each check the native media clock first, because a reload re-sends Icecast's burst and the listener hears audio twice; a regained link reads it through the pending check it brings forward, and with none pending reloads at once. Every load is checked even when it reports no state (iOS drops a repeated Loading, #2143), and an automatic reload is a failure until it plays, so a hung station backs off to 60 s. None runs during an iOS audio interruption (a call, Siri), which freezes the clock without a state event. Its header explains the rest.
- **Playback lines go through `plog` (`src/hooks/usePlayer.ts`), and are redacted before they are stored** (#2140). Release builds keep the last few hundred for the About sheet's Share playback log, so `src/lib/playback-log.ts` strips the station password, the Station login, URL queries and route device names first; a line that can carry a new kind of secret needs a rule and a test there. `PlaybackLog.add` never throws, because `plog` runs mid-reload and ahead of each event's dispatch: a line it can't redact is lost, never stored raw (#2160).
- **Every request to a station sends the Station login as a header, from `loginHeaders` (`src/lib/api.ts`)** (#764, #1873): API calls go to the credential-free base, and image sources carry scoped headers too. Android's fetch and image loaders, and AVPlayer, ignore URL userinfo.
- **A station's body read ends at its own deadline, and an abort alone doesn't end it** (#2163): `readJson` (`src/lib/api.ts`) gives every JSON read `FETCH_TIMEOUT_MS` for the headers, then the same again for the body, and stops at the caller's signal, so a new read goes through it, never a bare `res.json()`. It aborts the request and races the read, because native `text()` never settles after a cancel on iOS and resolves truncated on Android; its header explains. The directory reads through it too, with one `FETCH_TIMEOUT_MS` across headers and body (`src/lib/directory-read.ts`). A test of it never awaits a read that can stall: a promise that never settles hangs `npm test` instead of failing it.
- **A Station login is checked with the station before it is saved, and only a 401 whose `WWW-Authenticate` asks for Basic counts as a proxy refusing it** (#1873): `src/lib/station-login.ts` says which check reads the login. A 403, a timeout or a network error never refuses one or stops the player, and nothing probes the stream, which would count a phantom listener. `/station-auth` reads a challenge of any scheme, like any 401 that is not the controller's own, as unverified on purpose (`stationAuthResult`), so a proxy never makes the app forget a station password; never unify the two rules.

### v1.30 playback recovery

A connection that briefly reaches playing and closes still counts against stream-recovery backoff. `gate-resume.ts` resumes only the station instance the password gate held, with a verified station password; explicit pause/tune-out clears that intent.
