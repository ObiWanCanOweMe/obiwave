# Upstream SUB/WAVE v1.10.0 Integration and Release Design

## Objective

Integrate immutable upstream SUB/WAVE `v1.10.0` into ObiWave as a true two-parent merge, preserve the fork's stricter and additive contracts, merge the reviewed result into `develop`, cut `v1.10.0-obiwave.1`, publish the complete fork image matrix, deploy it to production, and verify the live station.

## Upstream behavior to adopt

The composed fork includes all v1.10.0 behavior, notably:

- TanStack Query ownership extended across the admin application;
- show and persona roster sorting, filtering, and tags;
- retention of the selected genre filter after choosing a suggestion;
- corrected platter deck sizing;
- leading and trailing dead-air detection plus non-destructive track-edge trimming;
- remote analyzer path fallback to a source URL when local paths are unavailable;
- persisted album and artist identifiers so block rules remain effective;
- front-padding for listener-request intros over station beds;
- on-demand jingles that air at full level and support arbitrary duration;
- accompanying schema, MCP, documentation, generated-asset, and verifier changes.

## Fork contracts to preserve

Upstream behavior is composed with, not substituted for, the fork's existing contracts:

- listener authentication, station-scoped stream credentials, secret redaction, and guarded station switching;
- provider-keyed LLM/search credentials, URLs, Kagi support, and LiteLLM behavior;
- strict settings/request schemas, generated mirrors, migrations, and field-error ownership;
- authoritative original-year clearing and cache reconciliation from the v1.9.0 review fixes;
- grounded agent-mode skill abstention when no usable data source ran;
- QueueHeldBadge standalone rendering and production-equivalent transition-duration harness behavior;
- station lifecycle, player hydration, stream-format selection, and query-cache ownership;
- queue timing, voice serialization, metadata, transition, archive, and idle-policy behavior;
- fork analyzer, embeddings, audio moods, stems, Observatory, and CUDA extensions;
- portable CPU TTS plus strict CUDA TTS and analyzer variants;
- immutable image identity, exact CUDA digest handoff, Portainer deployment, bounded deadlines, rollback, and public health probes;
- isolated verification that cannot access production credentials, state, or services;
- historical recovery manifests and immutable-artifact validation;
- vulnerability scanning remains manual-only: `.github/workflows/scan-images.yml` retains only `workflow_dispatch`, is never invoked by this work, and gains no scheduled, reusable, build, release, recovery, or deployment dependency.

No iOS or Android EAS release is part of this integration.

## Conflict and semantic-merge policy

For every textual conflict and every high-risk auto-merged overlap:

1. establish the upstream v1.10.0 contract from its implementation and tests;
2. establish the fork contract from implementation, tests, and prior release evidence;
3. preserve upstream behavior;
4. preserve additive or stricter fork behavior;
5. compose both at the narrowest owning boundary;
6. record the decision and executable proof in a task-local conflict ledger;
7. add or update a focused regression when existing tests do not prove the composition;
8. stop for operator direction if the contracts are genuinely incompatible.

No conflict may be resolved wholesale with `ours` or `theirs`. Generated schemas, theme tokens, embedded CLI assets, and lockfiles are regenerated from composed source rather than hand-edited.

The admin Query migration is one coherent subsystem. Its shared query-key factories, invalidation rules, auth boundaries, station switching, discovery hooks, settings panels, schedule state, and library cache must be audited together. In particular, upstream's broader Query ownership must retain the fork's authoritative per-row era-clear results and must not reintroduce duplicate in-flight requests, retry storms, stale station data, or cross-station cache leakage.

High-risk controller audits cover silence trimming, analyzer path selection, source completeness, album/artist identifier persistence, queue drain timing, request-intro padding, full-level jingle routing, voice serialization, Liquidsoap metadata, and fork CUDA/analyzer behavior.

## Verification architecture

### Baseline and focused gates

Use Node `22.23.2` and locked dependencies. Before merging, prove the complete fork baseline. The approved baseline is controller 823/823, all declared web test scripts, MCP lint, CLI typecheck, and native-app typecheck/contracts. Any environmental native-addon issue must be corrected without a source change before interpreting test results.

After composition, run focused tests for every conflict and high-risk overlap. Any product regression follows observed RED, minimal correction, focused GREEN, and broader rerun. Do not change passing behavior speculatively.

### Full gates

Before review and after every material correction, run:

- stable theme-token, schema, and embedded-asset generation;
- controller lint/typecheck and complete tests;
- web lint, every declared contract test, admin Query audit, browserless verifiers, and production build;
- MCP lint, CLI typecheck, and native-app lint/typecheck/contracts;
- complete repository CI, release, security-library, and deployment contract suites;
- YAML validation, `git diff --check`, conflict-marker scan, generated-artifact drift checks, and exact merge-parent proof;
- local native-architecture Docker smoke builds for representative publication images, with only task-local image references removed afterward;
- compose and release-topology assertions, including the manual-only scan trigger.

Admin/browser verification uses the repository `verify` skill with disposable state, spare ports, and a task-local dummy Subsonic backend. Production configuration, credentials, state, and services are prohibited during integration testing.

## Review and merge

Independently review the integration commit, any follow-up corrections, and the final branch. Critical or Important findings block progression and require a focused regression, minimal fix, affected gate rerun, and renewed review.

Push the exact reviewed head to a ready-for-review PR targeting `develop`. Merge only when base and head SHAs match the reviewed identities, required checks pass, the PR is mergeable, and no requested changes or unresolved review threads remain. Use a merge commit with an exact-head guard, then prove the expected upstream ancestry on remote `develop`.

## Release and image publication

Before release, prove `v1.10.0-obiwave.1`, its GitHub release, and its immutable image tags are absent. Dispatch `.github/workflows/cut-fork-release.yml` with version `1.10.0`, revision `1`, and the exact merged `develop` SHA. Verify the immutable tag and GitHub release target that SHA and retain upstream `v1.10.0` ancestry.

The tag-triggered publication workflow must build and push the complete fork matrix, including service images, portable CPU TTS, CUDA TTS, lean/heavy/CUDA analyzer variants, and AIO variants. The exact same-run CUDA TTS digest artifact must flow directly from build to deployment.

The manual-only scanning policy is a release invariant. Do not invoke `scan-images.yml`, add a scan dependency, or restore any automatic trigger during integration, publication, deployment, or rollback.

## Deployment and rollback

The production environment-scoped Portainer job deploys the immutable release only after its build, mirror, and release gates pass. It captures the prior stack before mutation and reserves enough time to restore and verify that snapshot within the workflow timeout.

Target verification requires:

- public health plus a bounded, decodable, non-silent MP3 sample;
- exact release image references and registry digests for the running first-party stack;
- analyzer health on the intended lean, heavy, or CUDA flavor and the expected capabilities;
- CUDA TTS health with zero unexpected restarts and CUDA runtime attestation;
- both Chatterbox and PocketTTS loaded;
- one valid positive-duration disposable synthesis from each engine with no fallback;
- removal of only the exact disposable probe files;
- no CPU fallback in CUDA startup or synthesis logs.

If target verification fails, restore and verify the exact prior stack. A successful rollback still means deployment failed. A rollback failure is an incident and stops all further mutation.

## Evidence and completion

Task-local ignored evidence records identities, conflict resolutions, tests, reviews, PR/merge state, release/tag state, image digests, deployment target and prior version, health/audio/GPU/TTS probes, rollback evidence, warnings, cleanup, and unresolved concerns.

Completion requires:

- an exact two-parent v1.10.0 integration merged into `develop`;
- every required verification and independent-review gate passing;
- immutable `v1.10.0-obiwave.1` published from the merged SHA;
- automatic vulnerability scanning still absent and manual dispatch still available;
- production running the target release with verified health, audio, analyzer, image identity, CUDA TTS, and PocketTTS;
- disposable probes removed and the tracked integration worktree clean.
