# Upstream v1.1.1 Integration Design

## Goal

Integrate the exact upstream SUB/WAVE v1.1.1 release into ObiWave from the
current `origin/develop`, make upstream behavior authoritative wherever it
supersedes fork behavior, and semantically port the completed Kagi Web Search
provider onto the resulting v1.1.1 codebase.

The integration must preserve the fork capabilities that remain intentional:

- provider-owned Kagi Search API support;
- fork-qualified image publication;
- immutable mirroring of the upstream CUDA analyzer image;
- fail-closed CUDA operation on Ark;
- Portainer production deployment and rollback;
- the shared Icecast configuration renderer; and
- the explicit absence of remote analyzer URL handoff and Odin behavior.

Upstream v1.1.1 contains the v1.1.0 feature and bug-fix release plus the v1.1.1

- the Rundown board redesign and edge resizing;

## Merge Policy

Cleanly merged upstream paths remain upstream-owned unless an existing fork
contract test proves that an intentional fork capability was lost.

Conflict resolution follows these rules:

1. Accept upstream behavior when it fully replaces the fork implementation.
2. Preserve only the listed fork boundaries.
3. Re-express a preserved boundary through the current upstream architecture
   rather than restoring an obsolete pre-v1 module or interface.
4. Regenerate derived files from their canonical sources.
5. Do not perform unrelated cleanup or refactoring.

The pre-merge comparison predicts six textual conflicts.

### `docker/broadcast-entrypoint.sh`

### `web/components/admin/schedule/SchedulePanel.tsx`

### `web/components/player/PlayerShell.tsx`

### `CLAUDE.md` and `web/CLAUDE.md`

## Generated Assets

`cli/src/assets.generated.ts` is generated output. Do not resolve it by choosing
one side or hand-editing merged fragments. Resolve its canonical Compose,
environment, and deployment inputs first, then run the CLI asset generator and
commit the regenerated result.

The controller theme-token mirror is handled the same way: regenerate it from
the canonical theme source and require a clean follow-up generation.

## Kagi Semantic Port

The completed Kagi feature on `feature/kagi-web-search` is ported after the
upstream merge and conflict-resolution commit. Its old commits and pre-v1
structures are not merged.

Kagi remains a straight provider behind the existing `searchWeb()` contract:

```ts
type SearchResponse = {
  answer: string;
  results: Array<{ title: string; content: string }>;
};
```

Kagi uses the v1 Search API and returns an empty `answer`. It does not use
FastGPT, promote answer-generation fields, or fall back automatically to
another provider.

### Provider-Owned Credentials

Saved credentials are owned by provider:

```ts
search: {
  provider: 'duckduckgo' | 'tavily' | 'brave' | 'searxng' | 'kagi';
  apiKeys: {
    tavily?: string;
    brave?: string;
    kagi?: string;
  };
  baseUrl?: string;
}
```

The effective credential rules are:

| Provider | Saved override | Environment fallback |
| --- | --- | --- |
| Tavily | `search.apiKeys.tavily` | `SEARCH_API_KEY` |
| Brave | `search.apiKeys.brave` | `SEARCH_API_KEY` |
| Kagi | `search.apiKeys.kagi` | `KAGI_API_KEY` |

Kagi never reads `SEARCH_API_KEY` or another provider's saved key. Admin-saved
keys win over environment fallbacks. Public and Admin settings responses expose
presence sentinels, never secret values. Omitting a key preserves it, a
non-empty value replaces it, and JSON `null` explicitly clears it.

A legacy `search.apiKey` migrates only when its saved provider identifies the
credential as Tavily or Brave. Ambiguous legacy keys are ignored.

### Request and Response Contract

Kagi requests:

```http
POST https://kagi.com/api/v1/search
Authorization: Bearer <effective Kagi key>
Accept: application/json
Content-Type: application/json
```

The body uses the straight search workflow, JSON format, a limit of ten, and
safe search. Optional day, week, and month recency values become UTC
`filters.after` dates.

The response adapter:

- chooses search/news buckets deterministically;
- strips markup and decodes entities;
- caps snippets at 300 characters;
- discards unusable entries;
- deduplicates by normalized URL or content identity;
- returns at most ten results; and
- safely returns an empty result for malformed success payloads.

### Runtime and Operator Surfaces

The semantic port includes:

- provider dispatch, readiness, and provider-aware caching;
- production search and non-mutating key probes;
- actionable authentication, quota, timeout, network, and malformed-response
  errors;
- Doctor knowledge and diagnostics;
- Admin provider selection, saved-key status, environment-fallback status,
  save, clear, and test actions;
- live settings behavior without a restart;
- root environment and controller secret propagation;
- all controller-bearing Compose shapes;
- documentation; and
- regenerated CLI assets.

The existing Kagi fixtures and tests are behavioral acceptance criteria.
Module paths and interfaces may be adapted to v1.1.1, but credential isolation,
request behavior, redaction, migration, and UI state semantics must remain
unchanged.

## CUDA and Deployment Boundary

ObiWave continues to mirror the exact upstream CUDA analyzer image into:

```text
ghcr.io/obiwancanoweme/subwave-analyzer-cuda:<fork-qualified-release-tag>
```

For an ObiWave release derived from v1.1.1, the mirror source is:

```text
ghcr.io/perminder-klair/subwave-analyzer-cuda:1.1.1
```

That upstream amd64 image exists. The mirror must retain digest equality,
immutable tag preflight, authenticated scanning, and deployment ordering.

Ark's Portainer manifest continues to reserve the NVIDIA device, set
`ANALYZE_DEVICE=cuda`, and use the fail-closed command that prevents the
analyzer server from starting when PyTorch cannot see CUDA. No Odin target,
remote analyzer URL handoff, fork-built CUDA analyzer, or mutable `latest` tag
is restored.

## Error Handling

- A conflict whose correct ownership cannot be established stops the merge for
  review.
- A Kagi behavior that cannot be expressed through the v1.1.1 interfaces stops
  the port for design review; obsolete v0.47 modules are not restored as a
  shortcut.
- Generated-file drift is fixed at the canonical source, not in generated
  output.
- Test, scan, immutability, CUDA, deployment, credential-redaction, and
  URL-handoff-absence gates are not weakened to make the integration pass.
- No release tag is created and no production deployment is triggered as part
  of the integration branch.

## Commit Structure

The implementation should remain reviewable in this order:

1. the exact-tag non-fast-forward upstream merge with semantic conflict
   resolutions;
2. focused Kagi behavior commits, organized around provider credentials,
   runtime adapter/probes, Admin UI, and documentation/configuration;
3. generated theme and CLI assets;
4. any narrowly scoped integration fixes discovered by the acceptance gate.

The final history must not contain a merge of `feature/kagi-web-search`.

## Success Criteria

- ObiWave contains the exact upstream v1.1.1 release with auditable merge
  ancestry.
- Upstream v1.1.1 behavior is authoritative except at the explicit fork
  boundaries.
- The AIO release path no longer depends on the NodeSource shell installer.
- Kagi works as a dedicated-key straight Search API provider through runtime,
  Admin, diagnostics, configuration, and documentation.
- Existing search providers cannot consume Kagi credentials, and Kagi cannot
  consume theirs.
- Ark continues to deploy the mirrored upstream CUDA analyzer and fails closed
  without CUDA.
- URL handoff and Odin remain absent.
- Generated assets are canonical and every acceptance gate passes.
