# v1.7.0-obiwave.1 security-policy recovery design

## Outcome

The immutable `v1.7.0-obiwave.1` release and all ten image tags already exist at
merged source commit `62c7c9cf9f73256a4499d4b0aad9b3388866a46b`. Publication run
`31518940240` built and scanned every image, then failed closed at the aggregate
Trivy policy with 55 violations. Production deployment was skipped and Ark was
not changed.

Recovery will preserve the existing tag and image digests, update only the
reviewed policy data and immutable recovery allow-list, then rescan and deploy
the exact existing artifacts through a manual protected workflow. It will not
rebuild, republish, retag, overwrite, or create a replacement release.

## Root cause and risk decision

The 55 violations have three causes:

1. `v1.7.0-obiwave.1` is absent from the release-aware CUDA digest map even
   though the mirrored CUDA repository digest exactly matches upstream
   `ghcr.io/perminder-klair/subwave-analyzer-cuda:1.7.0` at
   `sha256:8fc7c81ea43a118d1c9d79da14986efa4876674745ac6ed6af166c202439990b`.
2. Trivy newly reports CVE-2026-58050 in eight images. The flaw requires an
   attacker-controlled SSH public-key-subsystem response and a 32-bit integer
   multiplication overflow. Every affected published image is `linux/amd64`
   and/or `linux/arm64`; none contains a 32-bit runtime manifest. The seven
   fork-built occurrences are therefore accepted as `unreachable`, scoped to
   the exact package/version and images. The CUDA occurrence remains
   `upstream-mirror`, scoped to its exact immutable upstream digest.
3. Acceptances for superseded libssh2 CVEs CVE-2026-55199/CVE-2026-55200 and
   ffmpeg CVE-2026-66041 no longer match a current finding. Those exact stale
   records are removed; unrelated acceptances are unchanged.

The Debian security tracker currently lists the affected Debian versions as
undetermined and no fixed version is reported. Recovery does not claim a
package fix; it records the reviewed architecture reachability decision and
keeps the normal acceptance expiry mechanism.

## Recovery workflow

Add manual-only `.github/workflows/recover-v1.7.0-obiwave.1.yml`, following the
proven fully-published recovery shape:

1. Verify the public tag/release, source commit, pinned scanner, and all ten
   remote tag digests against the checked-in immutable manifest.
2. Rescan tag-plus-digest references through `scan-images.yml` and require the
   aggregate policy to pass with zero violations.
3. Enter the protected `production` environment only after validation and
   policy succeed.
4. Reverify all immutable artifacts immediately before deploying
   `v1.7.0-obiwave.1` through the existing Portainer release client.

The workflow contains no build, push, tag creation, release creation, or
registry mutation command.

## Verification

Test-first coverage must prove:

- v1.7 CUDA pin success, cross-release mismatch rejection, and unknown-tag
  rejection;
- the exact checked-in recovery manifest and tamper rejection;
- exact acceptance presence/removal and successful replay of the downloaded ten
  scan reports with zero violations;
- workflow identity, immutable validation, policy dependency, protected deploy,
  and absence of build/push/retag behavior;
- the complete release/CI/deploy/security contract suite remains green.

After review and merge, dispatch the recovery workflow once. Completion requires
ten digest-qualified scans, aggregate policy success, protected deployment,
stable digests, production health and now-playing data, correct auth routing,
an MP3 sample with the expected content type and audible signal, and no restart
regression.
