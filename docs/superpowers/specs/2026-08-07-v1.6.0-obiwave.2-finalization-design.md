# v1.6.0-obiwave.2 Identity-Only Finalization Design

## Context and outcome

Release `v1.6.0-obiwave.2` was cut from merge commit
`28076250da60844457973794933b5af3b82fa1dc`. Publication run
`31208279448` passed the release gate, published all ten immutable images, and
completed all ten Trivy scans. Its aggregate policy then failed closed because
`scripts/security/trivy-policy.mjs` did not yet contain a release-aware CUDA
repository-digest pin for `v1.6.0-obiwave.2`. Production deployment was skipped.

The recovery will preserve the tag, GitHub release, images, scan evidence, and
failed publication run. A reviewed follow-up commit will record the exact
ten-image identity, add the missing CUDA digest pin, and add a manual no-build
finalizer. That finalizer will validate the immutable release identity, rescan
every image by repository digest, apply the normal aggregate policy, and deploy
the existing `.2` release through the protected production environment only if
every gate passes.

## Considered approaches

### Identity-only finalization (selected)

Commit the exact release manifest and CUDA pin, then reuse the established
`validate -> vulnerability-policy -> deploy-production` recovery pattern. This
preserves the already-published release and produces complete audit evidence
without granting package-write authority.

### Cut `v1.6.0-obiwave.3`

A new release could include the digest pin in its tagged source, but it would
rebuild and republish ten unchanged images solely to correct release-control
metadata. It is safe but wasteful and leaves `.2` as an unnecessary abandoned
release.

### Move or overwrite `.2`

Changing the Git tag, GitHub release target, or any image is rejected. It would
break the repository's immutable-release contract and invalidate existing scan
and registry evidence.

## Components and data flow

1. Add `v1.6.0-obiwave.2` to the literal approved recovery identities in
   `scripts/release/recovery-manifest.mjs` and commit the matching JSON manifest
   under `security/releases/`.
2. Add the `.2` CUDA digest to `PINNED_CUDA_IMAGE_DIGESTS`. This changes no
   vulnerability acceptance; it only binds existing `upstream-mirror`
   acceptances to the reviewed repository manifest.
3. Add `.github/workflows/finalize-v1.6.0-obiwave.2.yml`, manual dispatch only.
   Its validation job verifies the tag, public GitHub release, scanner, all ten
   tag digests, and the checked-in manifest. Its reusable scan job consumes the
   recovery manifest so all pulls are digest-qualified. Its production job
   repeats the full public-release, tag, scanner, and ten-image digest preflight
   after protected-environment approval, then invokes the existing Portainer
   release script with the literal `.2` tag.
4. The workflow has no build matrix, package-write permission, registry-copy
   operation, mutable tag input, or path capable of publishing an image.

## Failure handling

- Any tag, release, scanner, source, image-set, order, or digest mismatch stops
  validation before scanning or deployment.
- Any scanner or aggregate-policy failure stops deployment.
- Any release or registry identity change while deployment waits for protected
  environment approval is caught by the deployment-time preflight.
- Portainer deployment retains the existing automatic rollback and health,
  now-playing, auth-routing, MP3 content-type, sample-size, and audio-level
  checks.
- The original failed publication run remains unchanged as audit evidence.

## Testing and completion criteria

Test-driven changes will first make the recovery-manifest, CUDA policy, and
workflow-contract suites fail for the absent `.2` identity and finalizer. The
minimal implementation will then make those focused suites pass, followed by
the complete release/security contract suite and repository release gate.

Completion requires a reviewed and merged recovery PR, a successful manual
finalizer run, ten successful digest-qualified scans, a passing aggregate
policy, production deployment of exactly `v1.6.0-obiwave.2`, and successful
post-deployment probes. No existing release artifact may change digest.
