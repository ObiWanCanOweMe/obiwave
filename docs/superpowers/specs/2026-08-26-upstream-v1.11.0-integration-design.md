# Upstream SUB/WAVE v1.11.0 Integration Design

## Objective

Integrate immutable upstream SUB/WAVE `v1.11.0` into ObiWave as a true two-parent merge, preserve the fork's stricter and additive contracts, and merge the reviewed result into `develop`. Integrate the complete upstream source tree, including native iOS and Android support code, while explicitly excluding mobile publication, fork release creation, image publication, and production deployment from this task.

## Upstream behavior to adopt

The composed fork includes all v1.11.0 behavior, notably:

- searchable, grouped, and deferred admin settings with a compact station switcher;
- station-scoped native-app credentials, credential vault storage, authenticated API calls, and onboarding/station management;
- iOS Live Activity source, Expo module/target configuration, lock-screen, Dynamic Island, and Apple Watch support code;
- a maximum-listener setting and Connect URLs that lead with the configured public stream URL;
- editorial-session-scoped DJ prompt memory;
- station ident language based on daypart rather than hour;
- cycling strict show playlists and show-specific recency ownership;
- reverse-proxy, split-port, update, rollback, concept, and private-station documentation;
- all accompanying schemas, generated assets, package metadata, tests, and configuration changes.

Native code is integrated and verified as source because it defines shared contracts consumed by controller and API behavior. No EAS invocation, native cloud build, TestFlight submission, App Store submission, Play build, APK distribution, or device installation is authorized.

## Fork contracts to preserve

Upstream behavior is composed with, not substituted for, the fork's existing contracts:

- the post-v1.10 manual-jingle marker provenance fix: automatic rotation can never acknowledge a pending manual FIFO reservation, manual markers remain durable across controller restart, and legacy markers fail safe to the bounded TTL;
- listener authentication, station-scoped stream credentials, secret redaction, and guarded station switching;
- provider-keyed LLM, search, TTS, and embedding credentials and URLs, including Kagi and LiteLLM behavior;
- strict settings/request schemas, generated mirrors, migrations, and field-error ownership;
- authoritative original-year clearing and cache reconciliation;
- grounded agent-mode skill abstention when no usable data source ran;
- Query-owned admin data, auth/station cache isolation, safe stale-result suppression, and authoritative schedule/library refreshes;
- queue timing, voice serialization, request intros, jingles, metadata, transitions, archives, idle policy, and stream buffers;
- analyzer, embeddings, audio moods, stems, Observatory, portable CPU TTS, and strict CUDA variants;
- immutable image identity, exact CUDA digest handoff, Portainer rollback contracts, and public health/audio verification code;
- isolated browser verification that fails closed on provenance and cannot contact production credentials, state, or services;
- the complete v1.10 integration's reviewed tests and generated assets;
- vulnerability scanning remains manual-only: `.github/workflows/scan-images.yml` retains only `workflow_dispatch`, is never invoked by this work, and gains no scheduled, reusable, build, release, recovery, or deployment dependency.

## Conflict and semantic-overlap policy

For every textual conflict and every one of the 41 shared changed paths:

1. establish upstream v1.11.0 behavior from implementation and tests;
2. establish fork behavior from implementation, tests, and prior review evidence;
3. preserve upstream novelty;
4. preserve additive or stricter fork behavior;
5. compose both at the narrowest owning boundary;
6. record the decision and executable proof in a task-local ledger;
7. add or update a focused regression where existing tests do not prove the composition;
8. stop for operator direction if contracts are genuinely incompatible.

The native-app credential subsystem is reviewed as one boundary: station model, storage, credential vault, API construction, StationContext, onboarding, station management, feed hooks, now-playing derivation, and player consumers must agree. Credentials must remain station-scoped, must not leak through logs or cache keys, and must clear or rebind correctly when a station changes.

The Live Activity subsystem is reviewed as source and build configuration: Expo app config, local module, target, Swift attribute definitions, TypeScript bridge, now-playing/voice-turn derivations, artwork handling, and tests must remain mutually coherent. Generated `ios/` and `android/` projects are not committed or published.

High-risk controller/runtime audits cover prompt-memory editorial boundaries, strict-playlist cycling and recency, daypart clock language, maximum-listener rendering, public stream URL normalization, Docker entrypoint/AIO parity, and all retained jingle/voice invariants.

The admin settings redesign is reviewed as one Query/form boundary: registry, section chrome, search, deferred mounting, settings hydration, protected secret previews, save payloads, station switching, and existing fork providers must remain coherent without retry storms, stale publication, or cross-station leakage.

## Verification architecture

### Baseline and merge characterization

Use Node `22.23.2` and locked dependencies. Before merging, prove the complete fork baseline from exact `bfd7bbe1`. Characterize every conflict owner and high-risk auto-merged overlap before resolution. Treat local runtime/toolchain drift as environmental until reproduced under the repository's supported versions.

### Focused verification groups

- Native credentials: storage migration, vault isolation, authenticated/anonymous requests, station switching, onboarding, and feed consumers.
- Live Activities: TypeScript derivations, attribute parity, native configuration contracts, voice-turn behavior, artwork and current-track updates.
- Controller: prompt-memory session scope, station ID daypart, strict playlist cycling/recency, maximum listeners, stream URL, settings persistence, and jingle provenance.
- Admin web: settings registry/search/deferred rendering, station switcher, provider secrets, Query ownership, generated schemas, and browser semantic verification.
- Runtime/deployment contracts: broadcast/AIO entrypoint parity, Liquidsoap rendering, compose topology, immutable publication/deployment contracts, and reverse-proxy documentation consistency.

Any product regression follows observed RED, minimal correction, focused GREEN, and a broader rerun. Do not change passing behavior speculatively.

### Complete gates

Before review and after every material correction, run:

- stable theme-token, schema, and embedded-asset generation;
- controller lint/typecheck and complete tests;
- web lint, every declared contract test, isolated browser verifiers, and production build;
- MCP lint and CLI typecheck;
- native-app lint, typecheck, every declared test script, package/config integrity checks, and source-level Live Activity tests, without EAS or store builds;
- complete repository CI, release, security-library, and deployment contract suites;
- YAML validation, `git diff --check`, conflict-marker scan, generated-artifact drift checks, and exact merge-parent proof;
- local native-architecture Docker smoke builds for the publication topology, with only exact task-local image references removed afterward and no prune;
- compose and release-topology assertions, including manual-only scan triggers and absence of scan callers.

Browser verification uses disposable state, spare ports, task-owned dummy Subsonic and LLM endpoints, fail-closed provenance, retained sanitized evidence, and exact cleanup. Production configuration, credentials, state, and services are prohibited.

## Review and merge

Independently review the integration commit, every follow-up correction, and the final branch. Critical or Important findings block progression and require a focused regression, minimal fix, affected-gate rerun, and renewed review. Minor findings are fixed or explicitly deferred with a costed rationale.

Push the exact reviewed head to a ready-for-review PR targeting `develop`. Merge only when base and head SHAs match the reviewed identities, required checks pass, the PR is mergeable, and no requested changes or unresolved review threads remain. Use a merge commit with an exact-head guard, then prove the expected upstream ancestry on remote `develop`.

## Explicit non-goals

- No `v1.10.0-obiwave.2` release.
- No v1.11 fork tag or GitHub release.
- No image publication or production deployment.
- No production access or health/synthesis probes.
- No EAS, TestFlight, App Store, Google Play, APK, or device distribution.
- No vulnerability scan execution and no automatic scan trigger.
- No unrelated refactoring or changes to the main checkout's existing edit or stash.
