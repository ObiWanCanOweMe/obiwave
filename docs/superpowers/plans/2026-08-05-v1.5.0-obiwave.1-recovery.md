# v1.5.0-obiwave.1 Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Safely recover and deploy the already-published immutable `v1.5.0-obiwave.1` images by making CUDA policy release-aware and adding a one-release, digest-qualified recovery path.

**Architecture:** Replace the global CUDA digest with a fail-closed release-to-digest map, make the existing CUDA acceptance prose truthful for both supported releases, and extend the literal recovery-manifest allowlist with the exact v1.5 artifact set. A manual v1.5 recovery workflow will validate and rescan the existing digest-qualified images before using the protected Portainer deployment job; it never builds, pushes, retags publicly, or creates a release.

**Tech Stack:** Node.js 22 ESM scripts and `node:test`, GitHub Actions reusable workflows, Trivy 0.67.2, Docker Buildx manifest inspection, GHCR, Portainer, GitHub CLI.

- Do not create `v1.5.0-obiwave.2` and do not rerun the standard publication workflow.
