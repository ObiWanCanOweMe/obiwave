# Upstream v1.3.0 Integration and Fork Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge exact upstream SUB/WAVE v1.3.0 into ObiWave, preserve intentional fork contracts, merge the verified PR, and publish and deploy `v1.3.0-obiwave.1`.

**Architecture:** Create one non-fast-forward merge whose second parent is exact upstream tag commit `c1ce23df`. Upstream owns v1.3 library, Fish TTS, analyzer, broadcast, picker, settings-limit, and UI changes; ObiWave's LiteLLM, Kagi, authenticated streaming, Ark edge/CUDA, immutable publication, and rollback behavior compose around them. After local and PR verification, cut the fork tag from merged `develop` and use the existing publication, scan, Portainer deployment, and audio verification gates.

**Tech Stack:** Git, Node.js 22, TypeScript, Express, React, Next.js, Expo, Docker/Compose, GitHub CLI and Actions, GHCR, SSH, Portainer, curl, jq, and ffmpeg.

## Global Constraints

- Branch: `integrate/upstream-v1.3.0`; original base: `22a156bbb94329ff0a192dd44ee0db25ffdf3349`.
- Merge exact `v1.3.0` commit `c1ce23df8acbeb759f32e4666f59bf517c2f67d0` with `--no-ff`.

- Preserve strict requests, LiteLLM, provider-owned Kagi, authenticated MP3/Opus/AAC/FLAC playback, Ark edge auth, exact CUDA mirroring, fail-closed Ark CUDA, Portainer deployment, and verified rollback.

- Regenerate CLI assets and theme tokens from canonical inputs.
- PR targets `develop` and merges with a merge commit.
- Release tag is exactly `v1.3.0-obiwave.1`; never overwrite or reuse it.
- Confirm Portainer endpoint 14 is connected before deployment can begin.
- Completion requires audible audio louder than `-50 dB`, not only a green health endpoint.
