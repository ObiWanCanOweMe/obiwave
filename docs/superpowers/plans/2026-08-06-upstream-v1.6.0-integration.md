# Upstream SUB/WAVE v1.6.0 Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge exact upstream SUB/WAVE `v1.6.0` into ObiWave, preserve fork-only behavior and safety contracts, verify the composed tree, and open a reviewed green pull request without merging or releasing it.

**Architecture:** Start from the committed design on `integrate/upstream-v1.6.0`, establish a clean full-suite baseline, and create one non-fast-forward merge whose second parent is the exact upstream tag. Resolve the six predicted conflicts explicitly, keep ObiWave's consolidated CI while porting upstream's schema gates, verify the auto-merged library/LLM/webhook surfaces with focused suites, then run isolated runtime, image, whole-repository, review, and GitHub PR gates.

**Tech Stack:** Git, Node.js 22, npm lockfiles, TypeScript 6/5.8, Vercel AI SDK 7, Zod 4, React Hook Form, Next.js 16, better-sqlite3/sqlite-vec, Docker Buildx, GitHub Actions, Trivy, GHCR, and Playwright-based isolated verification.

## Global Constraints

- Start from `origin/develop` commit `0e57fa1af15cdbfa944f005a7df2320ea5124f98` plus design commit `a3d5156b` and this committed plan.
- Upstream `v1.6.0` must resolve to `c9b4a24d363f44b002722750e6c0b6a7845cae7a`.
- Upstream `v1.5.0` must resolve to `8c01e979ebeea5c5ed6cac6658b5da14322b9d6d` and remain an ancestor of `v1.6.0` and the fork base.
- Create exactly one upstream merge commit; its second parent must be `c9b4a24d363f44b002722750e6c0b6a7845cae7a`.
- Upstream wins when it supersedes the same behavior; fork-only behavior remains; independent overlapping behavior is composed.
- Do not resolve an ambiguous conflict by accepting an entire side wholesale.
- Preserve fallback TTS, provider-owned credentials and URLs, private-station authentication, playback-format hydration, immutable release policy, vulnerability acceptance, recovery manifests, workflow topology, Portainer rollback, and analyzer-readiness checks.
- Every bug or missing composed behavior discovered during the integration enters a red-green test cycle before its production fix.
- Use disposable state and non-production ports for runtime verification; do not read or write the live station state.
- This phase opens a PR only. Do not merge it, create or move a tag, create a GitHub release, publish or retag an image, dispatch a release/recovery/deploy workflow, or change production.

Keep fork `normalizeTts`, `normalizeTtsFallback`, persona voice rules, and all non-webhook normalizers. Replace only the old hand-rolled `normalizeWebhooks` with:

```ts
export function normalizeWebhooks(raw: unknown): Webhook[] {
  if (!Array.isArray(raw)) return [];
  const rows: WebhookParsed[] = [];
  for (const item of raw) {
    if (!item || typeof item !== 'object') continue;
    const events = Array.isArray(item.events)
      ? item.events.filter((e: string) => (WEBHOOK_EVENTS as readonly string[]).includes(e))
      : [];
    const parsed = webhookSchema.safeParse({
      ...item,
      events,
      id: typeof item.id === 'string' && WEBHOOK_ID_RE.test(item.id) ? item.id : undefined,
      enabled: typeof item.enabled === 'boolean' ? item.enabled : undefined,
      authHeader:
        typeof item.authHeader === 'string' ? item.authHeader.slice(0, 500) : undefined,
    });
    if (!parsed.success) continue;
    rows.push(parsed.data);
    if (rows.length >= WEBHOOKS_LIMIT) break;
  }
  return resolveWebhookIds(rows);
}
```
