# v1.6.0-obiwave.2 Identity-Only Finalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bind the already-published `v1.6.0-obiwave.2` images to their reviewed identities, make the CUDA policy recognize that immutable mirror, and rescan/deploy the release through a no-build finalizer.

**Architecture:** Extend the existing literal recovery identity and release-aware CUDA digest maps for `.2`, then reuse the established three-job identity-only finalizer pattern. The workflow validates the public release and ten GHCR digests, invokes digest-qualified Trivy scans plus aggregate policy, and only then deploys the literal release tag through Portainer.

**Tech Stack:** Node.js 22 ESM and `node:test`; GitHub Actions reusable workflows; Docker Buildx registry inspection; GHCR; pinned Trivy 0.67.2; Portainer deployment script.

## Global Constraints

- Release tag stays exactly `v1.6.0-obiwave.2` at source commit `28076250da60844457973794933b5af3b82fa1dc`.
- Never build, push, copy, retag, overwrite, delete, or otherwise mutate an existing release image or Git tag.
- Scanner identity stays exactly the checked-in `security/trivy-scanner.json` identity.
- CUDA repository digest is exactly `sha256:cdf74b46d05a40d453b69541644b4e9e7c587617100a7484a616e358efd3c341`.
- The finalizer is manual-only, fail-closed, protected by the `production` environment, and has no package-write authority.
- Production deployment remains downstream of immutable identity validation and the complete ten-image vulnerability policy.
