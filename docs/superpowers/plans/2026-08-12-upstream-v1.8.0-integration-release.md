> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge exact upstream SUB/WAVE `v1.8.0` into ObiWave, preserve fork-only behavior and strict deployment safeguards, merge a reviewed green pull request, publish immutable `v1.8.0-obiwave.1`, and deploy it successfully to Ark.

**Architecture:** Work in the linked integration worktree and create one non-fast-forward merge whose second parent is the exact upstream tag. Treat both the six predicted textual conflicts and the high-risk auto-merged runtime/web/release paths as semantic composition boundaries; verify them with focused tests, full package and browserless gates, independent review, exact-head GitHub merge, digest-qualified image policy, and protected Portainer deployment.

**Tech Stack:** Git, Node.js 22, npm lockfiles, TypeScript, Zod 4, React, Next.js, dnd-kit, usehooks-ts, Python 3, Playwright, Docker Buildx, GitHub Actions, GHCR, Trivy 0.67.2, NVIDIA CUDA 12.4, and Portainer.

## Global Constraints

- Execute in `.worktrees/integrate-upstream-v1.8.0` on branch `integrate/upstream-v1.8.0`.
- Start from fork commit `1013e38c69b920e74ec54d1ec477422e96f30389` plus the committed design and plan documents. If `origin/develop` moves before the merge, stop, record the new identity in both documents, and rebase only the documentation commits onto that exact head before continuing.

- Upstream `v1.8.0` must resolve to `bc541fbecb6fe5ce5355cedb52a5cfcad965932f`.
- Create exactly one upstream integration merge commit. Its first parent is the pre-merge integration head and its second parent is exact upstream `v1.8.0`.
- Upstream wins when it supersedes the same behavior; fork-only behavior remains; independent overlapping behavior is composed.
- Do not resolve an ambiguous conflict by accepting an entire side wholesale.
- Preserve listener authentication, provider-keyed secrets and URLs, Kagi search, station/runtime behavior, query-cache ownership, exact-origin discovery, CUDA TTS, historical recovery, immutable artifact identity, vulnerability policy, deployment deadlines, and Portainer rollback.
- Every missing composed behavior discovered after the merge enters an observed RED, minimal fix, focused GREEN cycle before its production correction.
- Browser verification MUST use the `verify` skill, disposable state, fixed non-production ports, a task-local dummy Subsonic backend, and a fresh `SUBWAVE_VERIFY_PROVENANCE` marker. Never read production configuration or credentials and never contact production services for test setup.

- Keep both `subwave-tts-heavy` and `subwave-tts-heavy-cuda`; Ark continues to use the CUDA image without new required Portainer environment variables.
- Do not create iOS or Android EAS releases; upstream v1.8.0 has no native-app delivery requirement.
- A new scan-policy failure stops normal deployment. Recovery is a separate reviewed immutable-artifact change and may not retag, rebuild, approve blindly, or bypass policy.
- Do not claim completion unless the PR is merged, the complete live image matrix passes policy, Ark runs the target release and exact CUDA TTS digest, both TTS synthesis probes pass, public audio decodes with non-silent levels, disposable files are removed, and the tracked worktree is clean.
