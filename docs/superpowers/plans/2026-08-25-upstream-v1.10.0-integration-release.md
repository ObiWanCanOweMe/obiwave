# Upstream SUB/WAVE v1.10.0 Integration and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Merge exact upstream SUB/WAVE `v1.10.0` into ObiWave, preserve fork-only behavior and manual-only vulnerability scanning, merge a reviewed green PR, publish immutable `v1.10.0-obiwave.1`, deploy it to production, and verify the live station.

**Architecture:** Work in the existing isolated integration worktree and create one non-fast-forward merge whose second parent is the exact upstream tag. Compose upstream v1.10.0 behavior with fork contracts through focused owner tests, then run complete package/browser/container gates, independent review, an exact-head PR merge, and the existing environment-scoped Portainer deployment. Release publication must neither invoke nor depend on vulnerability scanning.

**Tech Stack:** Git, Node.js 22, npm, TypeScript, Zod, React, Next.js, TanStack Query, Python 3, SQLite, Liquidsoap, Docker Buildx, GitHub Actions, GHCR, Portainer, CUDA, Chatterbox, PocketTTS, and Playwright-backed verification.

**Spec:** `docs/superpowers/specs/2026-08-25-upstream-v1.10.0-integration-design.md`

## Global Constraints

- Execute in `.worktrees/integrate-upstream-v1.10.0` on branch `integrate/upstream-v1.10.0`.
- The fork base is exact `origin/develop` `3c898ff9666b8d1a6d66d58193fea538582fc249`; the approved design commit is `d27de5b3a25de7a4f0285aef02de1461ec81747f`.
- `v1.9.0` is `65c840ee9b099a8270cee4e88ab9993b9455c245`; `v1.10.0` is `fc7604ef95c717c32ce149e390bf09bca884134a`; the merge base must be exact v1.9.0.
- Create exactly one upstream integration merge commit whose second parent is exact v1.10.0. Never cherry-pick, rebase, force-push, or resolve an ambiguous conflict wholesale.
- Preserve all upstream behavior and additive or stricter fork behavior, including the v1.9.0 review fixes for authoritative era clears and zero-source skill abstention.
- Preserve authentication, station isolation, provider-keyed credentials and URLs, Kagi/LiteLLM, strict schemas, queue/voice ownership, analyzer extensions, CPU/CUDA images, immutable identities, Portainer deadlines, health probes, and rollback.
